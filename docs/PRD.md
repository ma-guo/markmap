# MarkMap 产品需求文档（PRD）

> 版本：v0.1（讨论稿）
> 状态：待评审
> 定位：旅行轨迹记录与分享工具

---

## 1. 背景与定位

### 1.1 现状
MarkMap 是一个基于百度地图的个人轨迹记录 App。当前数据模型为：

```
组 Group  ──<  线 Line  ──<  点 Point
```

已具备：三级列表、地图定位、按距离自动打点、手动标记、路线折线、点编辑、后台自动保存、自定义定位源，以及基于 12306 的列车运行图与余票查询。

### 1.2 产品初衷
记录**旅行过程中（飞行、乘火车、自驾、徒步等）的轨迹**，用于**保存与分享**。这类「一次完整行程的轨迹回看 + 分享」是普通地图 App 不具备的能力，是产品的核心差异点。

### 1.3 定位
> 记录一次出行的轨迹 → 保存为可回看的「行程」 → 一键分享给他人。

「组/线/点」在新定位下映射为：

| 概念 | 新语义 |
| --- | --- |
| 组 Group | 一次**行程 / Trip**（例如「北京→上海出差」） |
| 线 Line | 行程中的一**段**（例如 A-B、B-C、C-D，或飞行段、火车段） |
| 点 Point | 轨迹点 / 停留点 |
| 合并轨迹 | 把同一行程内的多段拼成一条完整 A-B-C-D 轨迹的**派生视图** |

## 2. 目标与非目标

### 2.1 目标（本期）
- G1 记录得住：断网、飞行模式、后台场景下轨迹不丢失。
- G2 拼得起来：同一行程的多段轨迹可合并为一条完整轨迹回看（核心场景）。
- G3 看得懂：提供里程、时长、速度、海拔等统计与剖面。
- G4 发得出去：支持地图截图分享卡与轨迹文件导出。
- G5 分得清：区分飞行 / 火车 / 自驾 / 步行等交通方式。
- G6 玩得下去：用成就、足迹、里程、年度报告等**本地玩法**提升留存与分享。

### 2.2 非目标（本期不做）
- 账号体系、云同步、多端协同。
- **社交互动暂不做**：好友同行合拍、排行榜、轨迹广场、点赞评论/关注等暂不纳入排期（见 9. M4）。
- 实时位置共享。
- 商业化（付费、广告）。

## 3. 目标用户与核心场景

### 3.1 用户画像
- 常出差/旅行的人：希望把每趟行程的轨迹留存并可分享。
- 旅行爱好者：希望回看「去过哪里、怎么走的」。
- 铁路/航空爱好者：对车次、航线轨迹有强兴趣。

### 3.2 核心场景

**场景一：跨段拼成完整行程（重点）**
> 用户从 A 飞到 B，在 B 停留中转，再飞到 C，最后坐火车到 D。用户为每段各建一条线：A-B、B-C、C-D。查看该组时，希望把它们**合并后**在**一张图**上看到完整的 A-B-C-D 轨迹，并标出 B、C 的停留时间。

**场景二：飞行中记录**
> 用户在飞行模式下打开 App 记录轨迹，中途无网络、无地图瓦片，落地后补全地名并分享。

**场景三：车次/航班补全**
> 用户没全程记录火车/飞机轨迹，输入车次或航班号+日期，还原参考轨迹作为行程的一段。

**场景四：分享行程**
> 用户把某次行程生成一张带路线图与统计信息的图片，发给朋友。

## 4. 名词定义

| 名词 | 定义 |
| --- | --- |
| 行程 Trip | 即现有「组」，一次出行的容器 |
| 段 Segment | 即现有「线」，行程中的一段轨迹，具有交通方式与起止时间 |
| 轨迹点 Point | 即现有「点」，含经纬度、海拔、时间、可选地址/描述 |
| 停留点 Dwell | 两个相邻段之间的衔接点，用户在此停留（如中转） |
| 合并轨迹 Merged Track | 将同一行程内多段按顺序拼接后得到的完整轨迹视图 |
| 断点 Gap | 两段轨迹端点距离超过阈值、无法自然衔接的位置 |

## 5. 功能需求

需求优先级：P0 = 本期必做；P1 = 本期应做；P2 = 后续版本。

### 5.1 行程 / 组模型（P0）

- FR-1.1 组升级为「行程」，新增字段：标题、描述、起止日期、封面图、行程标签。组列表展示行程名、日期范围、段数、总里程。
- FR-1.2 行程详情页汇总展示：所有段的概览、总统计、合并轨迹入口。

### 5.2 多段记录（P0）

- FR-2.1 段（线）新增字段：交通方式、颜色、起止时间、里程。
- FR-2.2 段列表按起止时间排序，用户可手动拖拽调整顺序。
- FR-2.3 新建段时默认继承行程的交通方式选择。

### 5.3 合并轨迹（P0，核心）

> 出发场景：一个组包含 A-B、B-C、C-D 三段，用户在 B、C 中途停顿；合并后应在同一张图查看完整 A-B-C-D 轨迹。

#### 5.3.1 合并规则（用户手动决定）

> 原则：**不设任何自动阈值**，怎么合并由用户决定。

- MR-1 **选择**：用户在行程内勾选要参与合并的段，可多选。
- MR-2 **顺序**：用户拖拽决定拼接顺序，**不自动按时间排序**。
- MR-3 **方向**：每段可单独切换正向/反向，默认正向。
- MR-4 **衔接**：按用户顺序首尾相接；相邻端点不重合时，默认用**虚线连接**表示位移/中转，用户可关闭连接线或选择留空。
- MR-5 **停留展示**：相邻段若都有起止时间，则在衔接点展示时间差；无时间则不展示。不做阈值判断。
- MR-6 **去重**：仅合并拼接处坐标完全重合的重复点，不改变用户选择。
- MR-7 **派生而非破坏**：合并是**视图/配置**，不修改原始段数据；原始段可单独查看与编辑。
- MR-8 **异常容错**：某段无点或点不足 2 个时跳过并提示「N 段未参与合并」。
- MR-9 **可保存**：合并选择与顺序可保存为行程的「合并方案」，下次直接打开。

#### 5.3.2 合并轨迹展示
- MR-10 地图上以一条整体轨迹展示，段与段之间用不同颜色区分，连接线用虚线。
- MR-11 衔接点可显示段名与时间差（有时间时）。
- MR-12 提供分段图例，可单独高亮/隐藏某段。
- MR-13 展示合并后的总里程、总时长、有效记录时长。

#### 5.3.3 合并轨迹交互
- MR-14 行程详情页提供「合并查看」入口，进入合并编辑页：勾选 → 排序 → 方向 → 预览 → 保存/分享。
- MR-15 允许在合并页长按某段进入该段的原始编辑。
- MR-16 允许把合并结果**导出/分享**（见 5.8）。

### 5.4 交通方式（P0）

- FR-4.1 支持枚举：飞行、火车、自驾、步行、轮渡、其他。
- FR-4.2 不同方式使用不同 marker 图标、折线颜色与线型。
- FR-4.3 行程详情可按交通方式筛选段。

### 5.5 离线与记录可靠性（P0）

- FR-5.1 断网/飞行模式下持续记录并本地落库，联网后再补地理编码。
- FR-5.2 无地图瓦片时支持「纯轨迹模式」（无需底图也能画线）。
- FR-5.3 轨迹清洗：按定位精度、速度突变过滤漂移点；重复点去重。
- FR-5.4 后台服务保活与异常恢复；应用被杀后恢复记录状态。
- FR-5.5 记录状态可视化：记录中/已暂停/已结束，以及已记录点数与里程。

### 5.6 统计与剖面（P1）

- FR-6.1 统计：总里程、总时长、有效记录时长、平均/最高速度、海拔升降、跨越城市/时区数。
- FR-6.2 高度剖面图与速度剖面图（飞行段可见爬升/巡航/下降）。
- FR-6.3 单段与整行程两级统计。

### 5.7 轨迹回放（P1）

- FR-7.1 按时间/顺序动画回放轨迹，带进度条与倍速（1x/2x/4x）。
- FR-7.2 回放时同步展示当前位置、速度、海拔。
- FR-7.3 多段行程回放可跨越停留点，展示时间轴。

### 5.8 导入导出与分享（P0）

- FR-8.1 导出：单段 / 单行程 / 全库，格式 JSON、GPX、CSV。
- FR-8.2 导入：GPX / KML / CSV / MarkMap JSON，导入为段。
- FR-8.3 分享卡：生成地图截图 + 行程名 + 日期 + 统计，支持系统分享。
- FR-8.4 系统分享/文件保存入口。
- FR-8.5 导入冲突处理：同名/重复轨迹提示覆盖或新建。

### 5.9 车次 / 航班轨迹补全（P1）

- FR-9.1 车次：12306 查询结果/运行图可一键保存为行程中的一段。
- FR-9.2 航班：内置机场库，按航班号/起降机场生成**大圆航线参考轨迹**作为一段（先不接入实际航路数据源）。
- FR-9.3 参考轨迹与真实记录轨迹区分显示（如实线 vs 虚线），可合并查看。

### 5.10 基础数据能力补强（P1）

- FR-10.1 回收站：组/线/点删除后可恢复、彻底删除、清空。
- FR-10.2 搜索：按名称/地址/描述过滤；全局点搜索。
- FR-10.3 手动排序：线、点拖拽排序。
- FR-10.4 批量操作：点多选，批量删除/移动/复制。
- FR-10.5 点增强：照片附件、标签、收藏，地图 marker 显示序号。

### 5.11 设置（P1）

- FR-11.1 合并显示设置：连接线显隐、分段配色；不设合并阈值。
- FR-11.2 单位与显示：米/公里、坐标精度、时间格式。
- FR-11.3 记录相关：采样间隔、距离阈值、震动、后台记录开关（沿用现有设置）。

### 5.12 互动与增长（本地玩法，P1，本期优先）

> 目标：用本地、零后端的方式提升留存与分享意愿。社交玩法本期不做（见 2.2）。

- FR-12.1 **成就徽章**：本地成就系统，解锁时弹出动画，提供徽章墙（已解锁/未解锁）。
  - 地理类（核心）：点亮省份、点亮城市、首次跨省、一次行程跨 N 省。
  - 交通类：首次飞行、首趟高铁、首次自驾/轮渡、多次中转。
  - 里程类：累计里程达标（见 FR-12.3）。
  - 特殊类：跨时区、最高海拔、夜航、最长单程。
- FR-12.2 **足迹点亮地图**：以**省/市两级**为核心，展示「已点亮 18/34 省、42/333 市」及覆盖率，支持分享。
- FR-12.3 **里程等级**：分别累计飞行、铁路、总里程，等级 + 进度条（青铜→白金），仿航司里程体验。
- FR-12.4 **年度 / 月度足迹报告**：总里程、最远一趟、到访城市数、轨迹热力地图、Top 路线，生成可分享长图。
- FR-12.5 **记录 Streak**：连续记录天数 / 本月行程数，强化打卡习惯。
- FR-12.6 **随机回忆**：展示「一年前的今天」的历史行程卡片。
- FR-12.7 **分享卡模板**：多套主题（极简/复古/航空风），支持成就与足迹地图水印。
- FR-12.8 **本地持久化**：新增成就/点亮数据表（`AchievementEntity`、`VisitedPlaceEntity`），首次启动可由历史点地址回填。
- FR-12.9 **城市/省份识别**：按 A+B+C+E 组合——后端结构化省市（含历史回填）→ `BDLocation` 记录时落库 → 地址文本解析 → 最近城市质心兜底；识别结果本地缓存。

**点亮规则**
- 同一城市多次到访只点亮一次，但记录到访次数与最近到访时间。
- **仅点亮端点城市**；航路/铁路**途经城市默认不点亮**（避免误记）。
- 直接 A→C 跨省，按 A、C 两端点点亮，途经省份不自动点亮。

## 6. 信息架构与交互流程

### 6.1 信息架构

```
行程列表（组）
 └─ 行程详情（组）
     ├─ 段列表（线）
     │   └─ 点列表（点）
     ├─ 合并轨迹视图（派生）
     ├─ 统计 / 剖面
     └─ 分享 / 导出
```

导航（沿用现有）：
`行程列表 → 段列表 → 点列表 → 点编辑`
`段列表 / 点列表 → 地图`、`段列表 → 行程合并地图`

### 6.2 合并轨迹主流程

1. 进入行程详情，点击「合并查看」。
2. 系统按规则（5.3.1）读取各段点集，计算顺序、方向、衔接、停留、断点。
3. 地图展示完整轨迹与分段配色、停留标记、断点虚线。
4. 用户在分段图例中开关某段，或长按某段进入编辑。
5. 用户可导出一张分享卡或 GPX。

### 6.3 异常态
- 无段 / 段无点：提示并禁用合并入口。
- 只有 1 段：直接展示该段，不做合并计算。
- 部分段无时间：按 `sortOrder` 排序并提示「部分段缺少时间，顺序按手动排序」。

## 7. 数据模型与迁移

### 7.1 现有模型（version = 1）
`GroupEntity` / `LineEntity` / `PointEntity`，均含软删除与 `sortOrder`。

### 7.2 建议变更（version = 2）

```text
GroupEntity   + description, startDate, endDate, coverUri
LineEntity    + transportMode, color, startTime, endTime
PointEntity   + speed, accuracy
```

- 合并轨迹为**运行时派生**，不新增表；如需缓存可后续加 `MergedTrackCache`。
- **必须写 Room Migration**，禁止继续使用 `fallbackToDestructiveMigration` 以免用户数据丢失。
- 新增字段全部可空或带默认值，保证向后兼容。

### 7.3 互动数据（version = 3）
```text
AchievementEntity   id, code, unlockedAt, progress, meta   // 成就/徽章
VisitedPlaceEntity  code(省/市), level, firstVisit, lastVisit, visitCount  // 足迹点亮
```
- 点亮与成就均可由历史 `Point` 数据回算重建，保证可恢复。
- 省/市编码建议使用统一的行政区划码，便于统计与展示。

### 7.4 交通方式枚举
`FLIGHT / TRAIN / DRIVE / WALK / FERRY / OTHER`

## 8. 非功能需求

- NFR-1 兼容：minSdk 28 / targetSdk 33，横竖屏与平板（已有 w600dp/w1240dp 资源）。
- NFR-2 性能：单段 1 万点、行程 10 段时合并计算 < 1s，地图渲染不卡顿。
- NFR-3 稳定性：记录进程被杀后可恢复；合并计算失败不影响原始数据。
- NFR-4 电量：后台记录控制唤醒频率，避免明显耗电。
- NFR-5 隐私：轨迹数据仅本地存储；分享需用户显式触发。
- NFR-6 隐私合规：百度定位/地图隐私协议保持现有初始化方式。

## 10. 验收标准（M1）

- AC-1 行程内 A-B、B-C、C-D 三段，用户可勾选并按自定顺序合并为一条 A-B-C-D 轨迹在一张图上查看。
- AC-2 合并顺序、每段方向完全由用户操作决定，不依赖时间或距离阈值。
- AC-3 相邻段端点不重合时默认以虚线连接，用户可关闭连接线或留空。
- AC-4 相邻段都有起止时间时展示衔接点时间差；无时间时不展示。
- AC-5 合并不修改原始段数据，原始段仍可单独查看/编辑/删除；合并方案可保存复用。
- AC-6 飞行模式/断网下记录的点在恢复网络后仍完整存在。
- AC-7 可导出一条段/行程的 GPX，并能在标准软件中打开。
- AC-8 可生成分享卡图片并调起系统分享。
- AC-9 升级安装后原有组/线/点数据不丢失（迁移验证）。
- AC-10 交通方式不同，地图样式可区分。

### M2 互动玩法验收
- AC-11 到访过的省/市可在地图上点亮，并显示覆盖率（已点亮/总数）。
- AC-12 同一城市重复到访只点亮一次，但到访次数与最近时间正确累计。
- AC-13 首次飞行/首趟高铁等成就可在满足条件后解锁并展示动画。
- AC-14 累计里程等级随新增行程实时更新。
- AC-15 年度/月度报告可生成并分享长图。
- AC-16 成就与点亮数据在应用重启后保持；历史点数据可回填。

## 11. 风险与开放问题

| 项 | 说明 | 处理 |

**已确认**
1. 互动玩法先做**本地玩法**，社交玩法（好友合拍/排行/广场）暂不做（M4）。
2. 徽章与足迹以**省/市**两级为主要点亮粒度。
3. **仅点亮端点城市**，途经城市默认不点亮。
4. 成就/足迹**按需计算**：进入成就/足迹页时基于历史数据计算，不做启动全量回填。
5. 省市识别采用 **A+B+C+E 组合**（后端结构化返回 + BDLocation + 地址解析 + 最近城市兜底）；后端 `notify.gyzuxing.com` 完全可控，承担历史回填。
6. 航班采用「内置机场库 + 大圆航线」参考轨迹（PRD FR-9.2）。
7. M1 离线范围：仅「纯轨迹兜底」——断网照常记录并按坐标绘制、地址待联网补全；不做离线地图下载（放 M3）。
8. M1 第一交付重点：**合并轨迹 + 分享卡**。
9. 行程**直接复用现有组**（Group = 行程），不新增独立 Trip 表。
10. **不设合并阈值**：合并的选择、顺序、方向均由用户手动决定；连接线默认虚线、可关闭。
